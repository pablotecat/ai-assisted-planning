# Adjuntos: una lectura antes del lote

## Prueba representativa

1. **Localizar:** fija adjunto, fuente, corpus y versión del encargo; usa el identificador y localizador realmente recibidos, no una URL inferida. Comprueba primero el inventario de `session_artifacts`: una copia completa, pertinente, accesible y vigente se reutiliza aunque haya caducado su URL. Un ID, ruta o hash por sí solo no concede acceso.
2. **Obtener:** comprueba el acceso al localizador o a la copia registrada. Sin copia válida, una URL caducada requiere recuperar un localizador autorizado; registra esa causa. Permiso denegado, copia alterada, versión distinta y cambio de alcance son causas diferentes: conserva el original y recupera solo lo necesario por una vía permitida.
3. **Descargar:** prueba un solo adjunto representativo antes de aplicar el método a los demás. Usa el contrato real del runtime: en Code Mode V2 verificado, `fetch` ofrece `bytes()`, no `arrayBuffer()`. Comprueba `ok`; la conversión binaria disponible es `(await respuesta.bytes()).toBase64()`. Un método ausente se abandona para todo el lote: corrige el método una sola vez y prueba la alternativa sobre el mismo adjunto, sin repetir el fallo en los demás.
4. **Presentar:** usa el archivo nativo, no base64 en una respuesta de texto. Un PNG puede capturarse directamente en el mismo `execute` con `tools.sesion.capture_agent_source({encargo_id, corpus, referencia, fuente, operacion_id, representacion:"png_base64", resultado:original})`, siendo `original` el base64 de los bytes recién obtenidos, sin retranscripción del modelo. Después llama a la herramienta directa `session_artifacts({action:"read", encargo_id, corpus, referencia, artefacto_id:instantanea_id, archivo})` con el ID y archivo devueltos, sin `cursor`, `limite`, `localizador` o vista textual. Esta lectura entrega el PNG íntegro como archivo nativo. Para una copia local ya autorizada existe `read`; para archivos aportados por el cliente, la presentación nativa `file:`/`data:` depende del cliente. La admisión V2 comprobada rechaza un adjunto `http:` directo; una URL en el texto no presenta una imagen.
5. **Leer:** confirma contenido visible concreto y su posición/página, separándolo de metadatos, texto alternativo y nombre del archivo. Solo entonces extiende el método validado al resto del lote compatible. HTTP 200, CRC, firma, dimensiones, captura por hash o `presentacion:"archivo_nativo"` no acreditan que el modelo lo haya recibido y comprendido. Si falla una etapa, mantén la lectura pendiente con etapa, efecto y siguiente acción; continúa únicamente partes independientes.

## Persistencia y límites

La captura PNG reutiliza el registro de fuentes, identidad, corpus y permisos existentes. Decodifica base64 y comprueba estructura/CRC; guarda bytes originales en el blob interno por hash y devuelve un archivo lógico `.png`. No acepta destinos arbitrarios ni convierte un publicador Markdown en escritor binario. Conserva `operacion_id` en un reintento idéntico; otra versión usa otra operación y no sobrescribe el original. La matriz de acceso sigue vigente: el Investigador no obtiene documentos locales crudos del Lector Documentación por este mecanismo; recibe sus conclusiones con citas.

Con guardado desactivado la captura devuelve exactamente `{guardado:false}` sin crear binarios ni control adicional. Una copia anterior solo se lee si sigue autorizada; de lo contrario usa una presentación nativa ya disponible sin persistencia añadida o declara bloqueada esa etapa y solicita el archivo por esa vía. No crees un temporal oculto para eludir el ajuste. La persistencia nativa de conversaciones de OpenCode es distinta del guardado del paquete.

El adaptador solo cubre PNG; otros formatos requieren una capacidad nativa compatible comprobada. Si falta, informa la capacidad mínima necesaria, sin implementar OCR, instalar servicios, ampliar permisos ni declarar una indisponibilidad global de visor. Las instrucciones definen la barrera de trabajo; no son un scheduler ni garantizan por sí solas la conducta del modelo.
