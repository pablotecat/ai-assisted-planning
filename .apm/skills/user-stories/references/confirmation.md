# Confirmación y restricciones

1. Separa el objetivo de su evidencia: incluye solo acuerdos aportados explícitamente en **Criterios de aceptación confirmados**; sitúa las condiciones sugeridas en **Propuestas de criterios — pendientes de confirmación**. Si no hay comprobaciones acordadas, indícalo. Identifica quién decide el comportamiento sin resolver. **Fin:** cada resultado sugerido se distingue de un requisito aprobado.
2. Sugiere condiciones discriminantes y resultados observables para éxito, excepciones significativas, límites, entradas inválidas o ausentes y acceso, según el objetivo. Si se desconoce el resultado esperado, pregunta y déjalo pendiente. Termina de añadir casos cuando uno más ya no aclare la intención; las permutaciones detalladas corresponden a los tests de desarrollo. **Fin:** cada caso propuesto puede aclarar una interpretación con consecuencias relevantes.
3. Para cualidades como velocidad, capacidad o facilidad de uso, pregunta qué roles y cargas importan, qué umbral o comparación cuenta y cómo se observará. Para usabilidad, usa una observación de usuarios representativa cuando proceda. Para una restricción transversal, identifica flujos afectados y cómo se revisitará la evidencia al cambiarlos. Marca cualquier objetivo ausente como **umbral pendiente**. **Fin:** alcance y método están visibles y cada objetivo no aportado permanece abierto.
4. Pide a la persona que decide sobre el producto que valide resultados buscados, excepciones y umbrales; invita al equipo de entrega y testers a revelar casos ausentes y verificar el comportamiento acordado. Enlaza especificaciones de interfaz o artefactos de diseño cuando su detalle ocultaría el objetivo. **Fin:** el solicitante distingue expectativas validadas, propuestas y decisiones humanas con responsable.
